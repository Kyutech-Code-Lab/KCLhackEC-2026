TypeScript

型はデータの約束

商品には必ず名前、価格、カテゴリがある。先に約束しておくと、後の実装が迷いにくい。

src/types/product.tstype
export type Product = {
  id: string;
  name: string;
  price: number;
  category: string;
  stock: number;
};
型は初心者には難しいが、商品データのチェックリストとして扱うと理解しやすい。
src/data/products.tsobject
{
  id: "gadget-speaker",
  name: "ポケットスピーカー",
  price: 6800,
  category: "ガジェット",
}

データ

オブジェクトは1件分のまとまり

  • `name` のような項目をプロパティと呼ぶ
  • 同じ形の商品を配列に並べる
  • 画面はこのデータから作る
オブジェクトは大量の変数をまとめたものとして説明する。

map

配列をカードの配列へ変換する

`map` は元の配列を直接変えず、表示用の新しい配列を作る。

ProductList.tsxReact
{products.map((product) => (
  <ProductCard
    key={product.id}
    product={product}
  />
))}
去年資料のmap説明を、Reactの一覧表示に接続する。

React

コンポーネントは再利用できる画面部品

Button

ProductCard

ProductList

部品化はコードを短くするだけでなく、変更する場所を絞るためだと伝える。

props

部品への入力

同じカードでも、渡す商品が変われば表示が変わる。props はその入力。

ProductCard.tsxprops
type ProductCardProps = {
  product: Product;
  isFavorite: boolean;
  onAddToCart: (id: string) => void;
};
propsは数学の関数のxのようなものという説明も使える。

useState

画面が覚えている値

検索キーワード、選択中のカテゴリ、お気に入り。画面の現在地を state として持つ。

searchTerm = "book"
はじめての Next.js ノート本
やさしい UI デザイン読本本
普通の変数では画面更新されないため、Reactのstateを使うと説明する。
search stateuseState
const [searchTerm, setSearchTerm] =
  useState("");

<Input
  value={searchTerm}
  onChange={(event) =>
    setSearchTerm(event.target.value)}
/>

検索欄

入力と state をつなぐ

  • `value` は今の値
  • `onChange` は変わった瞬間
  • `setSearchTerm` で画面が更新される
controlled componentという用語は出してもよいが、入力値をReactが管理していると説明する。

filter

条件に合う商品だけ残す

検索キーワード、カテゴリ、お気に入りなど、条件が増えても考え方は同じ。

productFilters.tsfilter
return products.filter((product) => {
  const matchesSearch =
    product.name.includes(searchTerm);
  const matchesCategory =
    product.category === selectedCategory;
  return matchesSearch && matchesCategory;
});
完成版では空検索や「すべて」を考慮していることを補足する。

useEffect

状態が変わった後の追加処理

検索結果更新、保存、タブタイトル変更など、表示以外の処理を置く場所。

page.tsxeffect
useEffect(() => {
  setFilteredProducts(
    filterProducts(products, searchTerm, selectedCategory)
  );
}, [searchTerm, selectedCategory]);
初心者が多い場合は依存配列を深掘りせず、監視対象として説明する。
localStoragebrowser
useEffect(() => {
  localStorage.setItem(
    "kcl-shop-favorites",
    JSON.stringify(favoriteIds)
  );
}, [favoriteIds]);

ブラウザ保存

再読み込みしても残す

  • `localStorage` はブラウザの機能
  • 文字列として保存する
  • Client Component の中で扱う
localStorage is not definedの原因を先回りして説明する。

Next.js

ファイルがURLになる

App Router では、`app/` の中に置いた `page.tsx` がページになる。

app/page.tsx/
app/order/page.tsx/order
app/products/[id]/page.tsx/products/abc
App Routerは現在のNext.js教材として扱う。pagesディレクトリは出さない。
Linknavigation
import Link from "next/link";

<Link href={`/products/${product.id}`}>
  詳細を見る
</Link>

ページ遷移

Next.js では Link を使う

商品カードから詳細ページへ。`product.id` をURLの一部に入れる。

aタグとの違いは細かくやりすぎず、Next.jsのページ移動にはLinkと覚えてもらう。

Dynamic Route

URLから1件を探す

`/products/gadget-speaker` の `gadget-speaker` を受け取り、同じ `id` の商品を探す。

[id]/page.tsxparams
const { id } = await params;

const product = products.find(
  (item) => item.id === id
);
paramsのPromiseはNext.js 16系の実装に合わせている。
OrderForm.tsxform
function updateField(field, value) {
  setFormData((current) => ({
    ...current,
    [field]: value,
  }));
}

フォーム

入力値も state で管理する

  • 名前、メール、住所を1つのオブジェクトで持つ
  • 変更した項目だけコピーして更新する
  • 送信後は確認表示だけを出す
バックエンド保存はしない。ハッカソン初期のプロトタイプとして十分使える。

大事な作法

state は直接書き換えない

避けるmutation
favoriteIds.push(productId);
setFavoriteIds(favoriteIds);
使うnew array
setFavoriteIds((current) => [
  ...current,
  productId,
]);
AGENTSのimmutability方針にも合う。初心者にはReactが変更に気づきやすい書き方として説明する。

よくあるエラー

詰まったら見る場所

エラーはだいたい同じところで起きる。原因を分類して直す。

症状見る場所
useState が使えない`"use client"`
ページが出ない`page.tsx` の場所
import できないexport とパス
一覧が警告`key={product.id}`
エラーを恐れさせず、見る順番を渡す。
